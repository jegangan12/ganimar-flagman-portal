# Изометрическая карта репозитория

Цель — не диаграмма «модуль → модуль», а читаемая модель системы, где **каждое
утверждение проверяемо по указанной строке кода**. Красивая картинка с выдуманными
подписями хуже, чем её отсутствие.

## Этап 1. Разведка — до единой строки разметки

Прочитай репозиторий и собери фактуру. Ничего не рисуй, пока список не закрыт.

- дерево файлов с размерами и количеством строк;
- точка входа и **порядок загрузки** — что подключает что и в каком порядке;
- зависимости: импорты, глобальные переменные, теги `script` / `link`, вызовы API,
  подписки, очереди;
- внешние границы: домены, сторонние сервисы, CDN, базы, платёжки;
- конфиги деплоя, заголовки, политика кэша, переменные окружения;
- **мёртвый груз**: файлы без единой входящей ссылки, побайтовые дубли, забытые
  артефакты (`grep`-ом по именам, а не на глаз);
- **расхождения**: где README, `docs/` или комментарии обещают одно, а код делает другое.

Каждый факт держи с адресом `файл:строка`. Если связи не видно в коде — её нет на карте.

Полезные проверки:

```bash
# что из ассетов реально используется
grep -oh "assets/[A-Za-z0-9/_-]*\.\(png\|jpg\|svg\)" -r --include=*.{html,js,ts,css} . | sort -u
# побайтовые дубли
md5sum assets/* | sort | uniq -w32 -d
# вес по каталогам
du -sh */ | sort -h
```

## Этап 2. Модель

| Сущность | Чем становится |
|---|---|
| Файл, модуль, хранилище, внешний сервис, точка монтирования | **узел** |
| Роль в системе — доставка, документ, рантайм, данные, ассеты, внешнее, документация, мёртвый груз | **слой** и цвет |
| Объём кода | **высота** постройки |
| Характер узла | **форма**: башня, плита, ворота, капсула, руина, парящая площадка |
| Реальный путь управления или данных | **ребро** с payload'ом и цитатой строки |
| Риск, техдолг, расхождение с документацией | **флаг** с описанием последствия |
| Именованный путь через граф | **трассировка** с пошаговым комментарием |

Обязательные трассировки: холодная загрузка, основной рабочий проход (рендер, обработка
запроса), выход за пределы системы. Полезная четвёртая — «что обещано в документации
и не подтверждено кодом».

## Этап 3. Страница

Один самодостаточный HTML-файл. Никаких CDN — карту должно быть можно открыть из
архива без сети.

**Проекция.** `x = (gx − gy)·TW`, `y = (gx + gy)·TH − z`. Коробка — три полигона:
верхняя грань светлее всех, правая (`gx + w`) средняя, передняя (`gy + d`) темнее всех.
Порядок отрисовки — по возрастанию `gx + gy` (дальнее раньше).
Хорошее соотношение плитки — `TW ≈ 54`, `TH ≈ 32`.

**Связи.** Квадратичная кривая между верхними якорями с подъёмом
`lift = 34 + расстояние · 0.2`, стрелка через `marker-end`. Частицы двигай через
`path.getPointAtLength()` в `requestAnimationFrame` — это и есть payload'ы.

**Панели.** Слева: слои с переключателями, легенда форм, легенда типов связей, список
трассировок. Справа: объяснитель — по умолчанию «как читать карту» и главные находки,
по клику на здание — досье с ролью, метриками, цитатами `файл:строка`, флагами и
списком входящих/исходящих связей.

**Управление.** Панорама перетаскиванием, зум колесом относительно курсора, «вписать»,
`Esc` — к обзору, `←` / `→` — шаги трассировки, видимый фокус для клавиатуры,
`prefers-reduced-motion`.

## Этап 4. Проверка глазами

Открой страницу в браузере, сделай скриншот и **посмотри на него**. Проверь: наложения
подписей, горизонтальный скролл, ошибки в консоли, читаемость при отдалении. Почини,
пересними, повтори. На узкой ширине (430 px) тоже.

```bash
# Chromium предустановлен, скачивать браузеры не нужно
node -e "require('playwright').chromium.launch({executablePath:'/opt/pw-browsers/chromium-1194/chrome-linux/chrome'})"
```

## Четыре грабли

1. **«Вписать» считает габариты вместе с чертёжной сеткой** — сетка нарочно шире
   содержимого, карта схлопывается в островок. Считай габариты только по слоям построек
   и связей.
2. **Подписи масштабируются вместе со сценой** и при отдалении становятся нечитаемы.
   Контрмасштаб `scale(0.92 / k)` вокруг якоря подписи держит постоянный экранный кегль.
3. **Подписи наезжают друг на друга** — постоянный кегль плюс сжимающиеся расстояния.
   Лечится уровнем детализации (ранг 1 виден всегда, остальное при `k ≥ 0.42`) и тёмным
   контуром `paint-order: stroke fill`.
4. **Горизонтальный скролл на телефоне** — у грид-элемента `min-width: auto`, и самый
   широкий потомок раздувает колонку. `.shell > * { min-width: 0 }`.

И главное про раскладку: разноси узлы **в экранных координатах**, а не в координатах
сетки. Шаг `+1` по `gx` и `+1` по `gy` даёт нулевое смещение по горизонтали — диагональ
из узлов схлопнется в одну вертикальную колонку. Проверяй `(gx − gy)·TW` и `(gx + gy)·TH`
до отрисовки.
