# Перенос предстартового блога на боевой сайт

Главная точка потери. Домен три месяца копил историю, а на релизе всё снесли и залили новое —
фора обнуляется, и проект снова стартует с нуля.

## Правило

**Ни один адрес, который был в индексе, не должен отдавать 404.**
Либо страница остаётся по тому же адресу, либо с неё стоит 301-редирект на прямой аналог.

## Порядок действий

### За неделю до релиза

1. Выгрузить полный список проиндексированных адресов:
   - Яндекс.Вебмастер → «Индексирование» → «Страницы в поиске» → выгрузка
   - Google Search Console → «Индексирование страниц» → выгрузка
   - плюс собственный `sitemap.xml`
2. Свести их в таблицу соответствия:

   | Старый адрес | Новый адрес | Действие |
   |---|---|---|
   | `/blog/tema-1` | `/blog/tema-1` | остаётся как есть |
   | `/blog/tema-2` | `/journal/tema-2` | 301 |
   | `/about` | `/o-nas` | 301 |

3. Проверить, что для каждой строки есть **прямой смысловой аналог**.
   Массовый редирект «всё на главную» поисковики трактуют как удаление страниц.

### В день релиза

4. Выкатить редиректы **одновременно** с новым сайтом, а не через день.
5. Сохранить тексты и заголовки статей. Переверстать оформление можно, переписывать содержимое — нет.
6. Обновить `sitemap.xml` под новую структуру и загрузить в обе панели.
7. Отправить на переобход: главную, хаб блога, 10-15 самых посещаемых страниц.
8. Проверить, что старые адреса отдают именно **301**, а не 302 и не 404:
   ```bash
   while read url; do printf "%s → %s\n" "$url" "$(curl -s -o /dev/null -w '%{http_code} %{redirect_url}' "$url")"; done < old-urls.txt
   ```

### Первые две недели после релиза

9. Ежедневно смотреть отчёт об исключённых страницах: там сразу видно отвалившееся.
10. Следить за ошибками 404 в логах хостинга и достраивать редиректы под реальные обращения.
11. Не менять структуру URL ещё раз. Каждая пересборка адресов стоит недель переиндексации.

## Чего не делать

- Не удалять статьи «потому что они не про новый продукт». Информационный трафик приводит
  людей на верх воронки — это и есть цель предстартового блога.
- Не закрывать блог в `noindex` «на время переезда».
- Не склеивать несколько старых страниц в одну новую без разбора: склейка теряет часть запросов.
- Не менять домен и структуру одновременно. Если переезд неизбежен — сначала одно, через месяц второе.
